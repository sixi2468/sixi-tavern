# 上线教程 · 从本地文件到互联网

> 面向"不写代码也要把它放上去"的场景。照着做，最快 **30 分钟**能拿到一个可访问的网址。
> 三种方案任选其一：**A 免费静态（推荐先做）**、**B Vercel（更简单）**、**C 国内服务器（要备案）**。

---

## 第 0 步：先在本地跑起来（3 分钟）

不要双击打开——有些浏览器在 `file://` 下会限制存储。用本地服务器：

```bash
cd site
python3 -m http.server 8000
```

浏览器打开 <http://127.0.0.1:8000>，能登录、能写笔记、能看到动画，就说明文件完整。

> Windows 没有 Python？安装 Python 3 后同上；或直接用 VS Code 的 Live Server 插件。

---

## 方案 A · Cloudflare Pages（免费、不限带宽，推荐）

**适合**：先上线验证，日活几百到几千都不花钱。不需要服务器、不需要备案（域名解析到境外）。

### A1. 准备账号

1. 注册 GitHub：<https://github.com>（免费）
2. 注册 Cloudflare：<https://dash.cloudflare.com>（免费）

### A2. 把文件放上 GitHub

最省事的方式（网页操作，不用命令行）：

1. GitHub 右上角 `+` → **New repository** → 名字填 `sixi-tavern` → **Public** → Create。
2. 进入仓库 → **Add file → Upload files** → 把 `site/` 里的**所有文件和文件夹**拖进去（注意：上传的是 `index.html` 这一层，不要多套一层 `site/`）。
3. 底部 **Commit changes**。

命令行方式（如果你已装 git）：

```bash
cd site
git init
git add .
git commit -m "四夕酒馆 v0.9"
git branch -M main
git remote add origin https://github.com/<你的用户名>/sixi-tavern.git
git push -u origin main
```

### A3. 建 Pages 项目

1. Cloudflare 控制台 → 左侧 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**。
2. 授权 GitHub，选中 `sixi-tavern` → **Begin setup**。
3. 构建设置：
   - Framework preset：**None**
   - Build command：**留空**
   - Build output directory：**`/`**（如果文件在根目录）；若你把文件放在子目录 `site/`，则填 `site`
4. **Save and Deploy**。等 30 秒，会给你一个 `https://xxx.pages.dev` 的网址。

打开它，能正常登录即可。**这就是你的网站了。**

### A4. 绑定自己的域名（可选，约 10 分钟生效）

1. 买域名（阿里云/腾讯云/Namesilo 均可）。若用 Cloudflare 托管 DNS，建议在 Cloudflare 里 **Add a site** 后把 NS 改过去。
2. Pages 项目 → **Custom domains** → **Set up a custom domain** → 填 `notes.你的域名.com`。
3. 按提示加一条 CNAME 记录（Cloudflare 托管的话一键完成）。
4. 证书自动签发，等 1–5 分钟，`https://` 生效。

> **不需要备案**：服务器在境外、域名解析到境外，不需要 ICP 备案。代价是国内访问速度一般（通常 100–300ms），但对文字站够用。

### A5. 以后怎么更新

改完文件，在 GitHub 网页上重新上传覆盖 → Cloudflare 自动重新部署（约 30 秒）。

## 方案 B · Vercel（更简单，但仅限非商业）

1. 注册 <https://vercel.com>，用 GitHub 登录。
2. **Add New → Project** → 选 `sixi-tavern` → Framework 选 **Other** → Deploy。
3. 得到 `https://xxx.vercel.app`。
4. 自定义域名：Project → Settings → Domains → 添加并按提示配 DNS。

> Vercel 免费版（Hobby）**禁止商业用途**。如果站内要放广告或收费，请用方案 A 或升级 Pro（$20/月）。

## 方案 C · 国内云服务器（要备案，速度最好）

**适合**：用户主要在大陆、要接国内广告联盟、要求低延迟。

### C1. 买服务器与域名

- 服务器：阿里云/腾讯云「轻量应用服务器」2 核 2G 3M，活动价约 ¥99/年。
- 镜像：**Ubuntu 22.04** 或 **Debian 12**。
- 域名：同一家买，方便备案。

### C2. 备案（7–20 个工作日）

1. 云厂商控制台 → **ICP 备案** → 按引导提交：主体证件、负责人照片、网站名称（不能含"酒馆"等敏感词？——"四夕酒馆"作为网站名一般可过，但要写清"个人博客/读书笔记"性质）。
2. 管局审核通过后，会给你备案号，必须显示在网站页脚。
3. 通过后 30 日内做**公安联网备案**。

> 备案期间网站不能对外提供服务（可以先用境外方案上线，备案下来再迁）。

### C3. 装环境

SSH 登录服务器后：

```bash
# 装 Nginx
sudo apt update && sudo apt install -y nginx

# 把网站文件传上去（本地执行）
scp -r site/* root@<服务器IP>:/var/www/sixi/

# 权限
sudo chown -R www-data:www-data /var/www/sixi
```

### C4. 配 Nginx

```bash
sudo nano /etc/nginx/sites-available/sixi
```

写入：

```nginx
server {
    listen 80;
    server_name notes.example.com;
    root /var/www/sixi;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location ~* \.(css|js|png|jpg|jpeg|webp|svg|woff2)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    gzip on;
    gzip_types text/css application/javascript image/svg+xml;
}
```

启用并重载：

```bash
sudo ln -s /etc/nginx/sites-available/sixi /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### C5. HTTPS

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d notes.example.com
```

按提示输入邮箱，选择自动跳转 HTTPS。证书 90 天自动续期。

> 或者用「宝塔面板」可视化操作：装宝塔 → 添加站点 → 上传文件 → 一键 SSL，适合不熟悉命令行的场景。

## 第四步半：现成的部署配置（省 1 小时）

`deploy/` 目录已经写好三套配置，复制到对应位置即可：

| 文件 | 放到哪 | 作用 |
|---|---|---|
| `_redirects`（已在站点根） | 与 `index.html` 同级 | 找不到的路径走 404，不会错误回退到登录页 |
| `deploy/netlify.toml` | 仓库根目录 | Netlify 缓存与安全头 |
| `deploy/vercel.json` | 仓库根目录 | Vercel 缓存与安全头 |
| `deploy/nginx.conf` | `/etc/nginx/sites-available/sixi` | 国内服务器 HTTPS + 缓存 + 404 |

细节见 `deploy/README.md`。

## 第五步（关键）：接上真正的后端

**为什么要接**：现在数据在每个人自己的浏览器里，A 写的笔记 B 看不到。要真正"分享"，必须有服务器存数据。

推荐 **Supabase**（开源、免费额度大、自带认证与行级权限）：

### 5.1 建项目

1. 注册 <https://supabase.com> → New project（选新加坡/东京节点，国内访问较快）。
2. 记下 `Project URL` 与 `anon key`（Settings → API）。

### 5.2 建表（SQL Editor 里执行）

> 完整脚本已放在 `supabase/schema.sql`（约 360 行，含触发器、行级权限、存储桶、初始屏蔽词），
> 直接整段粘贴到 Supabase → SQL Editor → Run 即可。下面是节选，方便你读懂每张表在做什么。

```sql
-- 用户资料（与 auth.users 一一对应）
create table profiles (
  id uuid primary key references auth.users on delete cascade,
  username text unique not null,
  birthday date,
  signature text,
  role text default 'user',          -- user / owner
  created_at timestamptz default now()
);

-- 分类
create table categories (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references profiles(id) on delete cascade,
  name text not null,
  sort int default 0
);

-- 书籍
create table books (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references profiles(id) on delete cascade,
  title text not null,
  author text,
  publisher text,
  isbn text,
  category_id uuid references categories(id) on delete set null,
  cover_url text,
  color int default 0,
  created_at timestamptz default now()
);
create index books_isbn_idx on books(isbn);

-- 笔记
create table notes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references profiles(id) on delete cascade,
  book_id uuid references books(id) on delete cascade,
  title text not null,
  content text not null,
  visibility text default 'public',  -- public / followers / private
  anonymous boolean default false,
  status text default 'pending',     -- pending / published / rejected
  tags text[] default '{}',
  like_count int default 0,
  tip_count int default 0,
  created_at timestamptz default now(),
  published_at timestamptz
);
create index notes_feed_idx on notes(status, visibility, created_at desc);

-- 评论
create table comments (
  id uuid primary key default gen_random_uuid(),
  note_id uuid references notes(id) on delete cascade,
  user_id uuid references profiles(id) on delete cascade,
  content text not null,
  anonymous boolean default false,
  status text default 'pending',
  like_count int default 0,
  created_at timestamptz default now()
);

-- 点赞（避免重复）
create table likes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references profiles(id) on delete cascade,
  target_type text not null,         -- note / comment
  target_id uuid not null,
  created_at timestamptz default now(),
  unique(user_id, target_type, target_id)
);

-- 关注
create table follows (
  follower uuid references profiles(id) on delete cascade,
  following uuid references profiles(id) on delete cascade,
  primary key (follower, following)
);

-- 屏蔽词
create table blockwords (
  id uuid primary key default gen_random_uuid(),
  word text unique not null,
  created_at timestamptz default now()
);
```

### 5.3 行级权限（RLS）

> 同样已包含在 `supabase/schema.sql` 里（`alter table ... enable row level security` 一节），
> 不需要再手动逐条执行。

```sql
alter table profiles enable row level security;
alter table books enable row level security;
alter table notes enable row level security;
alter table comments enable row level security;

-- 任何人可看公开资料
create policy "profiles readable" on profiles for select using (true);

-- 书只有本人能改，公开可见
create policy "books read" on books for select using (true);
create policy "books write" on books for all using (auth.uid() = user_id);

-- 笔记：已发布且公开的任何人可见；自己的全部可见
create policy "notes read" on notes for select using (
  status = 'published' and visibility = 'public' or user_id = auth.uid()
);
create policy "notes write" on notes for all using (auth.uid() = user_id);
```

> 这只是最小可用版本。上线前请把"关注者可见"和"匿名"逻辑补进策略，并在服务端做二次校验（前端隐藏不等于安全）。

### 5.4 把前端的 Store 换成 API

你的页面只调用 `Store.xxx()`，所以**只改 `store.js` 一个文件**即可：

```js
// 以「取信息流」为例
async function feed({ page = 0, size = 8, q = '', sort = 'new' }) {
  let query = supabase.from('notes')
    .select('*, book:books(*), author:profiles(username)')
    .eq('status', 'published').eq('visibility', 'public')
    .range(page * size, page * size + size - 1);
  query = sort === 'hot' ? query.order('like_count', { ascending: false })
                         : query.order('created_at', { ascending: false });
  const { data, error } = await query;
  if (error) throw error;
  return { items: data, total: data.length };
}

window.Store = { feed, /* ...其余方法逐个替换 */ };
```

页面里的 `await` 需要小改：把 `S.feed(...)` 改成 `await S.feed(...)`，其余 DOM 逻辑不动。

### 5.5 图片存哪

- Supabase Storage 建 `covers` 桶，公开读；
- 上传后拿 `getPublicUrl()` 存到 `books.cover_url`；
- 上传前在浏览器里压到 700px 宽（`shelf.html` 里的 `resizeImage()` 已经写好了这段逻辑，直接复用）。

### 5.6 邮箱登录

Supabase 自带 `auth.signUp` / `auth.signInWithPassword`，替换 `index.html` 里的 `S.login/S.register` 即可；记得在 Auth → Email 里配置 SMTP（否则只有 2 封/小时的测试额度）。

## 第六步：内容审核怎么接

三选一（按预算从低到高）：

| 方案 | 成本 | 接到哪 |
|---|---|---|
| 本地词库 + 人工 | ¥0 | 现有实现，够早期用 |
| 阿里云内容安全 | 约 ¥0.002/条 | 发布接口里调用 `TextModeration` |
| 腾讯云天御 / 网易易盾 | 类似 | 同上 |

接法（伪代码，放在 `addNote` 的服务端函数里）：

```js
const risk = await fetch('https://<你的后端>/api/audit', {
  method: 'POST', body: JSON.stringify({ text })
}).then(r => r.json());

if (risk.level === 'block')  return { error: '内容不合规，已拦截' };
if (risk.level === 'review') return { note: { ...note, status: 'pending' } };
return { note: { ...note, status: 'published' } };
```

> 记住一条：**前端过滤只能防君子，真正的审核必须在服务端做**。

## 第七步：广告位怎么接

1. 申请联盟：Google AdSense（需内容+隐私政策）或百度联盟（需备案+资质）。
2. 拿到代码后，在 `admin.html` → 广告位 → 粘贴 → 保存。
3. 代码生效位置：`tavern.html` 的 `adHTML()` 与 `note.html` 的正文底部。

如果要让代码真正执行（而不是显示文本），把占位 `<div>` 替换为：

```js
slotEl.innerHTML = adCode;           // 注意：只插入你自己后台的代码
slotEl.querySelectorAll('script').forEach(old => {
  const s = document.createElement('script');
  s.src = old.src; s.textContent = old.textContent;
  old.replaceWith(s);
});
```

**合规必须做**：Cookie 同意提示、隐私政策页、广告标识（"广告"二字）、未成年人保护声明。

## 第九步：常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 部署后刷新 404 | 静态托管没配 SPA 回退 | Cloudflare Pages 加 `_redirects`：`/* /index.html 200` |
| 样式没生效 | 路径大小写不一致（Linux 区分大小写） | 统一小写文件名 |
| 图片裂开 | 用了 `/assets/...` 绝对路径但站点在子目录 | 改相对路径 `assets/...` |
| 国内打开很慢 | 托管在境外 | 换国内服务器 + 备案，或上 CDN |
| 数据"丢了" | 清了浏览器缓存 | 这是原型限制；接后端后解决 |
| 登录后仍跳登录页 | 浏览器禁用了 localStorage | 换浏览器，或接后端 |
| 备案被驳回 | 网站名含"酒""馆"等易联想词 | 改网站名为"读书笔记分享"，或个人博客类目 |
