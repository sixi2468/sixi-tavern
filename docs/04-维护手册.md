## 1. 日常维护清单

### 每天（5 分钟）

- [ ] 打开后台看「待审核」，清空队列（积压超过 1 天，用户会觉得没人管）
- [ ] 看「驿站来信」，有举报立刻处理
- [ ] 扫一眼酒肆首页，有没有明显垃圾内容

### 每周（30 分钟）

- [ ] 导出一次数据备份（设置 → 导出全部数据）
- [ ] 看后台 DAU 曲线，掉超过 30% 要找原因（是不是打不开、是不是内容变差）
- [ ] 补 3–5 个屏蔽词（来源：这周被驳回的内容）
- [ ] 看服务器/托管有没有告警邮件

### 每月（1 小时）

- [ ] 检查域名与证书到期时间（证书一般自动续，但要确认）
- [ ] 清理无效账号与测试数据
- [ ] 更新一次隐私政策/用户协议的日期
- [ ] 复盘：哪类笔记点赞最高，下个月多推这类

## 2. 页面与样式

### 2.1 打开是白屏 / 只有背景色

**原因**：JS 报错导致页面没渲染。

**处理**：
1. 按 `F12` → Console，看第一条红色错误。
2. 若是 `Store is not defined` → `assets/js/store.js` 没加载成功，检查路径大小写。
3. 若是 `Unexpected token` → 某次编辑破坏了 JS 语法（常见于中文引号、少了逗号）。
4. 临时回滚：把上一版备份的 `assets/js/` 整个覆盖回来。

### 2.2 页面能开但完全没样式（纯文字）

**原因**：`main.css` 404。

**处理**：检查 `assets/css/main.css` 是否存在；部署到 Linux 服务器时**文件名大小写敏感**，`Main.css` ≠ `main.css`。

### 2.3 书封上的书名变成了方块 / 宋体

**原因**：设备没有楷体/行楷字体，落到宋体兜底。

**处理**：
- 正常现象，不影响功能；
- 想统一观感，就引入网页字体：把 `main.css` 的 `--brush` 改成 `'Ma Shan Zheng', var(--serif)`，并在 `<head>` 加：
  ```html
  <link href="https://fonts.googleapis.com/css2?family=Ma+Shan+Zheng&display=swap" rel="stylesheet">
  ```
- 国内访问 Google Fonts 不稳定，建议下载字体文件放 `assets/fonts/` 自托管，并用 `fonttools` 做子集化（只保留常用 3000 字，体积从 4MB 降到 200KB 左右）。

### 2.4 封面图不显示 / 显示成破图

**原因**：`book.cover` 存的是 base64 或外链，超长或失效。

**处理**：
- localStorage 单条约 5MB，图片超过 700px 宽会撑爆；
- 打开 `shelf.html` 重新导入封面（代码会自动压到 700px / JPEG 0.82）；
- 接了后端后改成存 URL，不再存 base64。

### 2.5 右下角水印挡住按钮

**处理**：改 `main.css` 的 `.watermark`：

```css
.watermark{ right:18px; bottom:10px; width:104px; opacity:.14; z-index:1; pointer-events:none; }
```

`pointer-events:none` 已保证不挡点击；若视觉上仍干扰，把 `opacity` 调到 `.08`，或 `@media (max-width:720px){ .watermark{display:none} }` 在手机端隐藏。

### 2.6 手机上排版错乱

**处理**：
- 先确认 `<meta name="viewport" content="width=device-width, initial-scale=1.0">` 在 `<head>` 里；
- 常见原因：某个元素固定宽度（如 `width:600px`）撑破屏幕，用 `overflow-x:hidden` 只是遮盖，正解是把宽度改成 `max-width:100%`；
- 用 Chrome 手机模拟器逐页检查 375px、414px 两个宽度。

### 2.7 顶栏图标看不清 / 太大

**处理**：`main.css` 里 `.nav-item img{height:32px}` 改数值即可；「竹海金茗」和「驿站」是同一套规则。

## 3. 数据与备份

### 3.1 数据到底存在哪

**原型版**：浏览器的 localStorage，键名 `sixi_v3`。
**接后端后**：Supabase（或你的数据库）。

### 3.2 换电脑/换浏览器，笔记没了

**原因**：localStorage 按「域名 + 浏览器」隔离，不跟随账号。

**处理**：
- 原型版无解，只能用「设置 → 导出 JSON」在旧设备导出，新设备导入；
- 这是**必须尽快接后端**的核心理由。

### 3.3 怎么备份

- **原型版**：设置 → 导出全部数据（JSON），存到网盘/本地，每周一次。
- **接后端后**：
  - Supabase：Database → Backups（Pro 版每日自动，保留 7 天）；
  - 自建：`mysqldump -u root -p sixi > sixi-$(date +%F).sql`，加到 crontab 每天 3 点；
  - 再每周 `scp` 一份到本地，**异地两份**才算备份。

### 3.4 怎么恢复

- 原型版：设置 → 导入数据 → 选 JSON → 刷新。
- 后端：Supabase 控制台 → Backups → Restore；自建用 `mysql sixi < backup.sql`。

### 3.5 导入 JSON 提示"文件读不出来"

**原因**：文件不是 UTF-8、或结构被改过。

**处理**：用 VS Code 打开，确认第一行是 `{`、最后是 `}`，且包含 `users` 和 `notes` 两个键；用记事本另存为 UTF-8。

### 3.6 提示"存储空间不足"（QuotaExceededError）

**原因**：localStorage 约 5MB 上限，封面图最占空间。

**处理**：
- 删掉几本带自定义封面的书；
- 或改 `resizeImage(f, 600, ...)` 里的宽度到 480；
- 根治：接后端，图片上对象存储。

## 4. 账号与权限

### 4.1 忘了密码

原型版没有找回功能。处理：
- 用馆主账号登录后台，或直接清空数据重置（会丢内容，慎用）；
- 接后端后用 Supabase 的 `resetPasswordForEmail`。

### 4.2 改用户名

设置 → 我的资料 → 改 → 保存。历史笔记会显示新名字（因为显示的是关联用户，不是快照）。

### 4.3 后台进不去

1. 确认登录的是 `owner@sixi.art`；
2. 账号的 `role` 必须是 `owner`；
3. 原型版可在浏览器控制台执行：
   ```js
   const d = JSON.parse(localStorage.getItem('sixi_v3'));
   d.users.find(u => u.email === '你的邮箱').role = 'owner';
   localStorage.setItem('sixi_v3', JSON.stringify(d));
   location.reload();
   ```

### 4.4 一定要删掉的三个后门（上线前）

| 位置 | 内容 | 为什么危险 |
|---|---|---|
| `index.html` | 「以馆主身份进入后台」按钮 | 任何人一键变馆主 |
| `admin.html` | 「以馆主身份进入」按钮 | 同上 |
| `store.js` | 演示账号明文密码 `123456` | 数据泄露 |

删除方法：直接删掉对应的 `<button>` 与绑定代码，或把 `owner@sixi.art` 的密码改成随机长串。

### 4.5 想让别人只能看、不能写

在 `notes` 表把该用户的 `status` 改为 `rejected`，或在后端加 `banned` 字段并在登录时拦截。

## 5. 内容与审核

### 5.1 正常内容被拦了（误杀）

**原因**：词库里有宽泛词，如「内部」「福利」「资源」。

**处理**：
- 设置 → 屏蔽词 → 点词后面的 `×` 删除；
- 或导入前先看 `assets/data/blockwords.txt`，把过宽的词删掉；
- 更好的做法：把词分「硬拦截」与「转人工」两档，前者只放明确违规词。

### 5.2 违规内容漏过去了

**原因**：变形写法（"加 微 信"）、拼音、谐音、图片里写字。

**处理**：
- 加正则：手机号 `1[3-9]\d{9}`、网址 `https?://`、QQ `[1-9]\d{4,10}`；
- 上线机器审核（阿里云内容安全/易盾），词库只做兜底；
- 开放举报入口（驿站里已有"内容举报"类型），人工兜底。

### 5.3 收到举报怎么处理

1. 后台「驿站来信」里找类型为「举报」的条目，内容里带原因与目标 id；
2. 用 id 在后台审核队列或前台定位内容（笔记页 URL `note.html?id=...`）；
3. 违规：删除/驳回 + 记 `user_id`；不违规：忽略并回信说明；
4. 同一用户累计 3 次违规 → 暂停发言（见 5.5）。

> 举报是"线索"不是"判决"，处理前先看原文。

### 5.4 匿名被用来骂人

**处理**：
- 匿名只是**前台不显示名字**，后端必须记录 `user_id`；
- 对同一 `user_id` 的匿名违规累计 3 次 → 暂停发言 7 天；
- 在用户协议里写明"匿名不免责"。

### 5.5 审核队列一直空 / 一直满

- 一直空：检查 `moderate()` 是否被调用；或 `reviewAutoPass` 被设为 true 且内容都不命中词；
- 一直满：说明词库太严或没人管，先批量通过明显正常的内容。

### 5.6 想加"先发后审"

设置 → 默认分享方式 → 审核方式改为「先发后审」。**不建议**：一旦出现违规内容，平台要担责。

## 6. 性能

### 6.1 首屏慢

- 检查图片：`assets/img/title.png` 现在 500KB 左右，可转 WebP 降到 60KB；
- 静态资源加缓存头（Nginx 配置见上线教程 C4）；
- 别在首屏加载大图，`loading="lazy"` 加上。

### 6.2 滚动卡

- 酒肆每批 8 条，一次渲染太多会卡；把 `state.size` 降到 6；
- 卡片里的 `box-shadow` 多，移动端可减到 1 层。

### 6.3 图片太大

统一压到 **宽 ≤ 700px、JPEG 质量 82**，单张 40–80KB。批量处理：

```bash
# 需要 ImageMagick
mogrify -resize 700x -quality 82 -format jpg *.png
```

### 6.4 字体闪烁

自托管字体时用 `font-display: swap`，或先把关键标题用图片（你现在的 logo 就是图，不闪）。

## 7. 部署与域名

### 7.1 改了文件，线上没变

1. 等 1 分钟（自动部署有延迟）；
2. 强制刷新 `Ctrl/Cmd + Shift + R`；
3. Cloudflare Pages → Deployments 看最新一次是否成功；
4. 检查是不是改了另一个仓库/分支。

### 7.2 刷新页面 404

单页应用需要回退。Cloudflare Pages 在根目录加 `_redirects`：

```
/*  /index.html  200
```

Nginx 用 `try_files $uri $uri/ /index.html;`。

### 7.3 域名打不开 / DNS 不生效

- `ping 你的域名` 看解析到哪；
- DNS 生效最长 24 小时（通常 10 分钟）；
- 国内域名解析到境外，可能被间歇性阻断，属正常。

### 7.4 HTTPS 提示不安全

- 证书是否过期（`certbot certificates` 查看）；
- 是否混入了 `http://` 的图片/脚本（混合内容会被拦）。

### 7.5 备案相关

- 大陆服务器必须备案，境外不需要；
- 备案号要显示在页脚并链接到 `https://beian.miit.gov.cn`；
- 换服务器/换主体要变更备案。

## 8. 广告

### 8.1 广告不显示

- 广告位是否启用（后台开关）；
- 代码是否被浏览器拦截（adblock）；
- 新站无流量时，联盟可能不填充，显示空白是正常的。

### 8.2 AdSense 审核被拒

常见原因：内容太少、缺隐私政策、缺"关于/联系"页、有版权内容。
处理：先补 20 篇原创笔记 + 三个静态页（关于、隐私、联系），再申请。

### 8.3 收益很低

- 国内流量单价天然低；
- 广告位别超过 2 个，多了影响体验且可能被判违规；
- 文字站更适合"打赏 + 会员"而不是纯广告。

### 8.4 合规底线

- 必须有 Cookie 同意提示（欧盟）与隐私政策；
- 广告要标"广告"；
- 不得对未成年人投放定向广告。

## 9. 迁移到后端（一次说清）

### 9.1 顺序

1. 建库建表（SQL 见上线教程 5.2）
2. 导出本地 JSON，写成导入脚本灌进库
3. 改 `store.js` 为 API 版（保持函数签名不变）
4. 页面里给异步调用加 `await`
5. 图片搬对象存储，`cover` 改存 URL
6. 认证换成 Supabase Auth
7. 审核改成服务端调用
8. 双跑一周（本地 + 线上），确认无漏再切

### 9.2 字段映射

| 本地字段 | 数据库字段 | 注意 |
|---|---|---|
| `users.pass`（哈希） | 不迁移 | 用 Auth 重设密码 |
| `books.cover`（base64） | `books.cover_url` | 先上传再写 URL |
| `notes.likes`（数组） | `likes` 表 | 一人一条，唯一索引 |
| `notes.likeCount` | `notes.like_count` | 用触发器或定时汇总 |
| `notes.tipped` | `notes.tip_count` | 支付流水另建表 |

### 9.3 迁移后自检

- 老笔记的作者对不对；
- 匿名笔记是否仍不显示名字（后台要看得到 user_id）；
- 点赞数是否一致；
- 同 ISBN 聚合是否还正确；
- 分页边界（第 1 页最后一条与第 2 页第一条不重复）。

## 10. 安全与合规

### 10.1 必须有的三个页面（已内置，需按实际主体改）

- `privacy.html` 隐私政策（收集了什么、存哪、存多久、怎么删）
- `terms.html` 用户协议（禁止行为、匿名不免责、内容授权）
- `about.html` 关于 + 联系我们（邮箱即可）

上线前请把文中的 **hello@sixi.art**、生效日期、运营主体换成你自己的；若用大陆服务器，页脚还要加备案号。

### 10.2 个人信息保护法（PIPL）要点

- 收集邮箱、生日属于个人信息，要有**明确告知与同意**；
- 生日属敏感信息倾向，建议改为"选填 + 仅用于生日祝福"；
- 提供**注销账号**与**导出/删除数据**的入口；
- 未成年人：14 岁以下需监护人同意，建议注册时加年龄确认。

### 10.3 技术侧

- 所有写操作在服务端校验 `auth.uid()`；
- 不要把 `service_role key` 写进前端；
- 上传文件校验类型与大小（防 webshell）；
- 数据库开 RLS；
- 管理后台加二次验证（邮箱验证码）。

## 11. 报错速查表

| 报错 | 位置 | 原因 | 处理 |
|---|---|---|---|
| `Store is not defined` | Console | store.js 未加载 | 检查路径、`<script>` 顺序（store 在 app 前） |
| `Cannot read properties of null` | Console | 元素 id 不存在 | 检查 HTML 是否被改 |
| `QuotaExceededError` | Console | localStorage 满 | 删封面 / 压缩 / 接后端 |
| `Unexpected token '<'` | Console | 把 HTML 当 JS 加载（404 返回了首页） | 修正资源路径 |
| 页面空白 + 无报错 | — | 内容被 `display:none` 或 z-index 遮挡 | 检查 CSS |
| 图片 404 | Network | 路径大小写 / 文件没上传 | 统一小写、重新上传 |
| 登录后跳回登录 | — | `requireAuth` 读不到 session | 检查是否禁用存储；换浏览器 |
| 评论不显示 | — | 状态仍是 pending | 等 4 秒或后台通过 |
| 部署成功但旧页面 | — | CDN 缓存 | 强制刷新、清缓存 |

## 12. 应急处理

### 12.1 出现违规内容（最紧急）

1. **先下架**：后台 → 审核队列/直接改状态为 `rejected`；
2. 记录 `user_id` 与时间（截图存证）；
3. 同一用户再犯 → 封禁；
4. 若涉及违法（涉恐、涉黄、诈骗），保存证据并向平台/网信部门报告；
5. 复盘：是词库漏了还是审核没开。

> 原则：**先处理，后解释**。内容事故的处置速度比措辞重要。

### 12.2 数据丢了

1. 先别写入任何新数据（避免覆盖）；
2. 找最近备份（本地 JSON / 数据库快照）；
3. 恢复后核对：用户数、笔记数、最新 10 条时间戳；
4. 复盘：为什么没备份/为什么备份没验证。

### 12.3 被刷（注册机、灌水）

- 注册加邮箱验证 + 图形验证码；
- 同 IP 限流（Nginx `limit_req`）；
- 新账号 24 小时内不能公开发言；
- 批量清理：按 `created_at` 与内容相似度筛。

### 12.4 服务器被打挂

- 云厂商控制台开 **DDoS 基础防护**；
- 静态站优先挂 CDN（源站被打时切到"仅缓存"模式）；
- 保留一份"维护中"静态页，随时切换。

### 12.5 自己误操作

- 改坏了 `main.css`：从备份恢复整个文件；
- 误删笔记：数据库有备份就恢复单表，没有就只能请用户重写（所以备份要验证）。
