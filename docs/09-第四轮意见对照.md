## 关于防滥用（第 2 条）

**先说 IP 限制的坑**：国内大量用户走运营商 NAT，一个出口 IP 可能几百人；校园网整栋楼一个 IP。
"同 IP 最多 5 个号"会误伤一大片。建议的组合是 **IP + 设备 + 邮箱域 + 行为**。

### 已经写进代码的（无需服务器）

| 规则 | 阈值 |
|---|---|
| 同一浏览器每日注册 | 5 个 |
| 同一邮箱连续登录失败 | 5 次 → 锁 10 分钟 |
| 发笔记 | 1 分钟内最多 3 条，之后间隔 20 秒；每日 20 篇 |
| 发评论 | 1 分钟内最多 3 条，之后间隔 6 秒；每日 100 条 |
| 注册 | 随机算式人机验证 |
| 内容 | 屏蔽词 + 长度上限 |

### 必须上服务端的三层（文档里有完整配置）

1. **Cloudflare**：Bot Fight Mode、WAF 速率规则（注册 5 次/10 分钟/IP、登录 10 次/10 分钟/IP、全站 120 次/分钟/IP）、Turnstile 人机验证；
2. **Nginx**：`limit_req` / `limit_conn` / `client_max_body_size 2m`；
3. **数据库**：`ip_attempts` 表 + `hit_limit()` 原子计数函数（SQL 已给出）。

处置要分级：**首次 → 人机验证；再次 → 限流；持续 → 封禁 24 小时**。一上来封 IP，误伤成本很高。

> 完整方案：`deploy/security.md`（含 Cloudflare 规则表、Nginx 配置、Supabase SQL、监控告警建议）。

## 关于 ISBN（第 8 条）

一句话：**没有单一免费源能覆盖大部分中文版本**。ISBN 是一个版本一个号，旧版、地方社、绝版书只能靠补录。

本站现在的顺序：

```
内置 28 本 → 本地补录/缓存 → 你配置的代理(可选) → OpenLibrary → Google Books → 手填
```

提升覆盖率的三步（按性价比）：

1. **接一个国内商用 ISBN 接口**（极速数据/聚合数据，按次约 ¥0.01–0.1），**走后端代理**，在 `config.js` 填 `isbnApi` 即可；
2. **开共享补录** `book_meta`：一个人填过，全站复用（表结构已在 `supabase/schema.sql`）；
3. 国家图书馆接口（权威，但需机构申请）；豆瓣官方 API 已关闭，不建议爬。

详见 `08-ISBN数据源.md`。
