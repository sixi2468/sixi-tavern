# ISBN 数据源怎么选（免费 / 商用 / 中文覆盖）

> 你要的是"大部分书籍、大部分版本都能查到"。先说结论：
> **没有任何一个免费 API 能做到**。ISBN 是"一个版本一个号"，
> 中文书的完整数据分散在国图、出版社、电商和豆瓣手里。
> 现实做法是「多源依次查 + 共享补录 + 允许手填」，本站已经是这个结构。

---

## 一、常见数据源对比

| 数据源 | 费用 | 中文覆盖 | 需要 Key | 说明 |
|---|---|---|---|---|
| **OpenLibrary** | 免费 | 弱 | 否 | 2000 万+ 条，英文书强；国内可访问性一般 |
| **Google Books** | 免费额度（约 1000 次/天） | 中等 | 可选 | 覆盖广，中文书名/出版社常有；国内网络常不可用 |
| **ISBNdb** | 付费（按套餐） | 弱 | 是 | 4300 万+ 条，19 个字段，英文书最全 |
| **Amazon PA-API** | 需联盟账号 | 弱 | 是 | 有价格与评论，仅适合电商场景，需满足销量门槛 |
| **中国国家图书馆** | 免费/需申请 | **强** | 是 | 权威，面向机构，申请流程长 |
| **豆瓣读书** | 无公开 API | **强** | — | 官方 v2 接口 2019 年已关闭；第三方代理不稳定且有合规风险 |
| **极速数据 / 聚合数据** | 按次（约 ¥0.01–0.1/次） | 较强 | 是 | 国内商用接口，按套餐计费，适合直接买服务 |
| **自建共享库** | 0 | 随使用增长 | — | 用户补录一次，全站复用（本站已内置本地版） |

> 价格与额度会变，下单前以官网为准。

## 二、本站现在的查询顺序

```
1) 内置常用书表（28 本，离线可用）
2) 本地补录 / 历史缓存（同一 ISBN 秒出）
3) 你在 config.js 配的 isbnApi（可选，建议指向自己的后端代理）
4) OpenLibrary
5) Google Books
6) 都失败 → 带入 ISBN，让你手填
```

手填保存后，这条记录会写进本地补录库，下次同一个 ISBN 直接命中。
接后端后，把本地补录换成共享表 `book_meta`（见 `supabase/schema.sql`），
就是"一个人补录，全站受益"。

## 三、想让中文覆盖率更高，按这个优先级做

### 1. 先接一个国内商用接口（最省事）

极速数据、聚合数据一类都提供 ISBN 查询，按次计费。
**不要在前端直连**（Key 会泄露），加一个后端代理：

```js
// 你的 Edge Function / Node 接口
export default async function handler(req) {
  const isbn = new URL(req.url).searchParams.get('q');
  const r = await fetch(`https://api.jisuapi.com/isbn/query?appkey=${KEY}&isbn=${isbn}`);
  const j = await r.json();
  return Response.json({
    title: j.result?.title || '',
    author: j.result?.author || '',
    publisher: j.result?.publisher || '',
    cover: j.result?.pic || '',
  });
}
```

然后在 `assets/js/config.js` 里：

```js
isbnApi: 'https://your-api.example.com/isbn?q={isbn}',
```

前端会自动优先用它，失败再回落到 OpenLibrary / Google。

### 2. 接国家图书馆（权威，但门槛高）

适合机构或有正式主体的项目：需提交申请，接口以 MARC/XML 为主，字段要自己映射。
拿到后同样包一层代理，转成 `{title, author, publisher, cover}` 即可。

### 3. 豆瓣：不建议直接爬

官方 API 已关闭；现存"接口"多为第三方代理，随时失效，且抓取违反其服务条款。
如果一定要用，只能做**人工辅助**：在书页给一个"去豆瓣搜索"的外链，不自动抓取。

### 4. 共享补录（长期最有效）

中文书的长尾版本（旧版、地方出版社、绝版）任何 API 都不全。
让用户补录一次、全站复用，半年后覆盖率会明显好于任何单一数据源。
本站已有 `book_meta` 表结构与本地缓存，接后端即可生效。

## 四、关于"大部分版本"

- ISBN 与版本一一对应：同一本书的第 1 版、第 2 版、精装、平装是不同 ISBN，必须分别收录。
- 因此不存在"一个接口全包"；要做的是**提高单次命中率**（多源）**和降低重复查询**（缓存/共享）。
- 建议给书加一个"版本"字段（出版社 + 出版年），同 ISBN 聚合时按版本分组，避免不同版本混在一起。

## 五、成本估算（按日活 1000、日均查询 300 次）

| 方案 | 月成本 |
|---|---|
| 只用免费源 | ¥0（但失败率高） |
| 国内商用接口（按次） | 约 ¥90–900，取决于单价 |
| ISBNdb 套餐 | 数美元起，英文书为主 |
| 自建共享库 + 免费源 | ¥0 + 少量人工补录 |

**建议**：先用免费源 + 共享补录跑起来，等"查询失败率"超过 20% 再买商用接口。
